# The Pusey Corpus — reproducible harvesting + public search

This project aims to create a **full-text searchable concordance of the major works of E. B. Pusey**. Its source of truth is the owner's [bibliography](https://sites.google.com/view/drpusey/works).

**Status at handoff:** The harvesting software, master bibliography, static-site generator, and GitHub Actions workflows are supplied. **The OCR files have NOT yet been downloaded in this package** because the file-building environment has no general outbound access to Archive.org. Do not mistake the bibliography for an indexed corpus. The included site reports the true number of indexed works.

## Source catalogue: first mandatory milestone (74 bibliography entries)

`data/source_registry.csv` is the **authoritative 74-row one-to-one register**. For each item, the intended output is ONE verified Internet Archive edition and ONE direct plaintext OCR file URL. It does not mean every work already has a scan: empty fields genuinely mean pending identification.

The source status is explicit:

- `verified_ocr` — bibliographic identity and actual plaintext have been independently inspected; safe to download/index.
- `confirmed_scan_ocr_pending` — a correct digitized edition identified, but the associated TXT file has not been confirmed.
- `ocr_file_listed` — Archive.org metadata confirms a TXT file is listed, but its contents/edition still require review.
- `candidate_found` — automatic search returned one or more possible OCR sources; **not approved for indexing**.
- `unmatched`, `no_candidate`, `error` — source remains unresolved.

`data/source_candidates.csv` collects up to four leads per unresolved title including the candidate title, author, edition year, full scan link, OCR filename, and *direct* OCR download URL retrieved from Archive.org metadata rather than guessed. The `Identify OCR sources for Pusey bibliography` GitHub Actions workflow builds that report. **Do not mark a source verified solely because the filename or title looks plausible**: check the actual volume and OCR contents. Some bibliography entries are Pusey prefaces or excerpts embedded in larger multi-author books; these need additional passage-range controls before claiming a strict Pusey-only search.

Only `verified_ocr` entries may be harvested by the automated downloader. After reviewing a candidate, record its Archive.org identifier and exact TXT URL in the 74-row source register, set `verification_status` to `verified_ocr`, and push that change. GitHub's harvest workflow can then collect it. This deliberately prevents conflating the first plausible Archive.org match with the correct Pusey work.

As of the initial release, *Daniel the Prophet* has one confirmed plaintext OCR URL and *Eirenicon* Part I has a confirmed scan awaiting OCR-file inspection; the remainder still need source matching. This is a **work-in-progress source catalogue**, not a claim that all 74 OCR files are present.

## What's included

- `bibliography.json` — 74 volume-level targets transcribed from the bibliography. Multi-volume works are split; two overlapping/revised editions are excluded from *default* indexing but retained in the bibliography.
- `harvest.py` — uses the Internet Archive advanced-search/metadata APIs, downloads plain-text OCR, retains the unaltered text, creates lightly cleaned copies, and records scan URLs/edition metadata. Questionable results are *flagged for review* rather than silently indexed.
- `build.py` — generates static HTML text-reading sections for every downloaded work and prepares the site for [Pagefind](https://pagefind.app/), a fast browser-based search index. Results identify title, year and text section, with highlighted snippets and a link to the full context.
- `local_search.py` — alternative **fully offline** search website using SQLite FTS5, with quoted-phrase search and highlighted context. Requires only Python and downloaded OCR.
- `.github/workflows/harvest.yml` — lets GitHub Actions perform the actual downloads; **you do not need to install Python on your computer** when using this route.
- `.github/workflows/publish.yml` — builds the website and Pagefind index and publishes it via GitHub Pages.
- `data/harvest_report.csv` — generated by the harvester; records which works were found, rejected, or still await identification.

## Recommended route: harvest and host in GitHub for free

1. Create a **public** GitHub repository, such as `pusey-corpus`, and upload the **contents** of this project folder (including `.github/workflows/`, which may require desktop Git or GitHub's uploader). Do not upload only the ZIP as one attachment. Better still, connect GitHub to ChatGPT and ask the assistant to help publish these files.
2. On GitHub open **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. Open **Actions → Identify OCR sources for Pusey bibliography** and inspect the generated `data/source_candidates.csv`. Select exactly one correct edition and OCR file for each bibliography entry before approval. Then open **Actions → Harvest OCR from Internet Archive → Run workflow**, choose `5` or `all` as the initial approved batch. The runner uses its own internet connection to query and download public texts. It saves raw and cleaned text back into your repository, along with source metadata. Running again skips completed works and unresolved candidates, so it progresses.
4. Once a batch is committed to the repository, **Build and publish Pusey Corpus** should deploy the updated searchable website automatically. Its URL will be `https://YOUR-USERNAME.github.io/pusey-corpus/` (assuming that repository name).
5. Open your Google Site in edit mode. Add a new page named **Search Pusey's Works**. Add the GitHub Pages address as an embedded page (or a prominent link). Confirm the embedded page renders; some hosts/browsers restrict framing, in which case an ordinary link is reliable.

*Note:* GitHub Pages has free usage and size limits. The source works are public domain, but please verify edition rights and licenses, especially modern reprints and third-party transcriptions, before publishing. GitHub Actions, GitHub Pages, Internet Archive downloads, and Pagefind availability are subject to the providers' current rules.

## Alternative: harvest locally

Requirements: Python 3.10+ and Node.js (only for creating the public search index).

```sh
python -m pip install -r requirements.txt
python harvest.py --limit 5
python harvest.py --all
python build.py
npx -y pagefind@1.4.0 --site site
python -m http.server 8000 -d site
```

Then open `http://localhost:8000/` in your browser. For further runs, `python harvest.py --all` skips downloaded files and items already requiring review. To retry unresolved works after fixing searches or sources, use `python harvest.py --all --retry-unresolved`.

## Completely offline search once texts are collected

You do not need a web host, Node.js, or a Pagefind build to search the texts on your own machine. After harvesting any works, run:

```sh
python local_search.py build
python local_search.py serve
```

Open `http://127.0.0.1:8765/`. This local search supports exact quoted phrases, work categories, and highlighted hits. Re-run `build` after harvesting additional texts. You may also use `python local_search.py search repentance` for a quick command-line search.

## Works that couldn't be auto-matched

Inspect `data/harvest_report.csv` and `data/records/{work-id}.json`. The latter contains candidates and scores. A human should verify the **edition**, **volume**, and **author** before choosing a scan. Make a simple JSON file, say `source-overrides.json`, mapping the work ID to a confirmed Internet Archive identifier:

```json
{
  "1855-the-doctrine-of-the-real-presence-as-contained-in-the": "VERIFIED_IA_IDENTIFIER"
}
```

This is an *example of the override format*, not a real identifier. Run:

```sh
python harvest.py --all --retry-unresolved --source-map source-overrides.json
```

The corpus has several special cases that need manual attention:

- `Plain Sermons` (1841) overlaps the revised *Parochial Sermons* III (1873).
- *Healthful Reunion* (1876) overlaps the earlier edition (1870).
- 1845 *Course of Sermons on Solemn Subjects* contains sermons by **other authors**, not only Pusey.
- Translations, patristic editions and prefaces contain varying proportions of Pusey's words and others' writings. The site **labels** these volumes by contribution category; it does not yet identify which sentences Pusey personally authored. A future, more rigorous authored-only search requires marking the relevant page ranges.
- CCEL's accessible *Minor Prophets* UTF-8 exports appeared to be chiefly `Image of page ...` placeholders rather than the prose; use genuine OCR from a scanned edition. The harvester tests for placeholder-heavy texts.
- Don't claim accurate printed page numbers on the basis of raw OCR. The first release uses section numbers and original scan links. Precise page mapping is a subsequent enhancement.

## Resilience and accuracy

Source discovery is deliberately separated from harvesting: automatic guesses cannot enter the public corpus until approved as verified. No automatic matching can guarantee the correct edition. Each downloaded file gets a provenance JSON with its URL, author/title metadata, length and hash. The original OCR is **never overwritten by cleanup**. All downloads can be retried and audited. There is no perfect duplicate-detection across editions at this stage; the two known reprints are excluded from the default index, with more overlaps to be reviewed after downloading.

## Project layout

```text
bibliography.json       master list of desired works
harvest.py              find and download scans
build.py                generate searchable reading pages
local_search.py         offline full-text SQLite engine and search website
requirements.txt        Python dependency (requests)
data/raw/               original UTF-8 OCR, one file per work
 data/clean/            lightly normalized copies
 data/records/          source metadata and status for every attempted work
 data/harvest_report.csv status report
site/                   generated pages; /pagefind added by indexing
.github/workflows/      cloud harvester and free website deployment
```
